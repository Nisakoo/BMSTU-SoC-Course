# SoC

Группа **ИУ5-51Б**, вариант **1**.

| Оценка | Задание |
| --- | --- |
| «3», №23 | Пройти по массиву и заменить нулями повторяющиеся подряд элементы. Программа — в машинном коде, данные и результат — в RAM. |
| «4», №17 | Управление гаражными воротами: кнопки пульта, концевые выключатели открытого и закрытого положения, ИК-датчик препятствия. Нужны ассемблер, программа на своей ISA и MMIO. |
| «5», №28 | Измеритель реакции: случайная задержка, светодиод, измерение времени до нажатия кнопки в микросекундах, лучший результат на 7-сегментном дисплее. Кастомная инструкция `HIGH_RES_TICK` захватывает значение таймера по фронту сигнала кнопки. |

## Запуск

Сборка программы ассемблером и запуск её на SoC в симуляции Verilator:

```bash
cargo run --bin asm -- asm/duplicates_to_zero.asm -o build/dup
cargo run -- build/dup
```

Первая команда создаёт `build/dup.rom.hex` и `build/dup.ram.hex`, см. [docs/ASM.md](docs/ASM.md). Вторая открывает окно отладки (GPUI):

- слева датчики (кнопки пульта и кнопка реакции действуют, пока их держат, концевики и ИК-датчик — переключатели) и выводы (8 светодиодов, привод ворот);
- справа RAM в hex: 1024 слова, по 4 слова в строке, адреса в словах, прокрутка колесом;
- сверху «Шаг» (один такт), «Запуск»/«Пауза», скорость (10, 1 000, 100 000 тактов в секунду, максимум) и счётчик тактов.

Процессор останавливается по `HALT`. Первый запуск дольше, потому что Verilator собирает модель; прерывать его до окончания сборки не стоит. Окно не требует Xcode: шейдеры GPUI компилируются при запуске (`runtime_shaders`).
