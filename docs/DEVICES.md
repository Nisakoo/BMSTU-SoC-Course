# Устройства

## Концепция

Устройство — отдельный модуль на Verilog. Он подключается к процессору через стандартную шину и занимает один или несколько адресов в области MMIO (`0xFFFFFC00`–`0xFFFFFFFF`, 1024 адреса). Процессор работает с устройством обычными `LOAD` и `STORE`. Внешний мир (кнопки, светодиоды, экран) подключён к устройству через его выводы, которые в симуляции ставит и читает Rust.

**Шина устройства.** Одинаковая у всех устройств:

| Сигнал | Откуда | Смысл |
| --- | --- | --- |
| `clk`, `reset` | общие | такт и сброс |
| `addr` (10 бит) | декодер адреса | смещение внутри MMIO: младшие 10 бит адреса |
| `we` | декодер адреса | 1 — запись |
| `wd` (32) | регистровый файл | записываемое слово |
| `rd` (32) | устройство | прочитанное слово; 0, если обращение не к нему |

**Адрес.** Устройство задаётся параметром `BASE` — смещением своего регистра. Оно само сравнивает `addr` с `BASE`: совпало — отвечает, нет — молчит (`rd = 0`, запись игнорируется). Адрес процессора равен `0xFFFFFC00 + BASE`; в команде `LOAD`/`STORE rd, imm(R0)` смещение `imm = BASE − 1024`.

**Чтение.** Ответы всех устройств объединяются по ИЛИ: `mmio_rd = a_rd | b_rd | …`. `BASE` разных устройств не должны совпадать.

**Подключение и отключение.** В `soc_top` добавляют экземпляр устройства и его `rd` в сумму `mmio_rd`; чтобы отключить, убирают оба:

```verilog
dev_timer #(.BASE(10'h000)) u_timer (
    .clk(clk), .reset(reset), .addr(mmio_addr), .we(mmio_we), .wd(rdata2),
    .rd(timer_rd), .time_us(time_us)
);
assign mmio_rd = timer_rd | capture_rd | ...;
```

**Выводы для Rust.** Внешние выводы устройств — порты `soc_top`. Rust ставит входы (кнопки) и читает выходы (светодиод, слова кадра) в цикле симуляции. Данные между процессором и устройствами идут только по шине.

**Связи с ядром.** У некоторых устройств есть прямые связи помимо шины. У захвата это `capt` и `nocap` для `HIGH_RES_TICK`.

## Список устройств

| Устройство | Модуль | `BASE` | Адрес процессора | Регистры |
| --- | --- | --- | --- | --- |
| Таймер | `dev_timer` | `0x000` | `0xFFFFFC00` | чтение: микросекунды с момента сброса |
| Захват | `dev_capture` | `0x010` | `0xFFFFFC10` | запись любого значения: взвод (`arm`) |
| Кнопка, концевик, датчик | `dev_button` | `0x020` | `0xFFFFFC20` | чтение: состояние входов, бит на вход |
| Светодиод | `dev_led` | `0x030` | `0xFFFFFC30` | запись и чтение: состояние светодиодов, бит на светодиод |
| Ворота | `dev_gate` | `0x040` | `0xFFFFFC40` | запись и чтение: бит 0 — открыть, бит 1 — закрыть |
| Дисплей | `dev_display` | нет | — | регистров нет |

Для `dev_button` и `dev_led` указан `BASE` по умолчанию. Несколько экземпляров подключают с разными `BASE`.

## Таймер

`rtl/dev_timer.v`. Параметры: `BASE` (по умолчанию `0x000`), `DIV` (тактов на микросекунду, по умолчанию 50).

- 32-битный счётчик микросекунд: делитель считает `DIV` тактов, затем счётчик увеличивается на 1. После сброса равен 0.
- Чтение по `BASE` даёт значение. Остальные адреса читаются как 0, запись игнорируется.
- Выход `time_us` идёт в захват.

## Захват

`rtl/dev_capture.v`. Параметр: `BASE` (по умолчанию `0x010`).

- Выводы: `btn` (кнопка, от Rust), `time_us` (от таймера), `capt` (захваченное значение) и `nocap` (1 — захвата не было) в ядро.
- Запись любого значения по `BASE` **взводит** захват и сбрасывает прежний результат. Читаемых регистров нет.
- Кнопка проходит синхронизатор из двух триггеров. Первый фронт 0 → 1 после взвода копирует `time_us` в `capt` и снимает захват со взвода: следующие нажатия не меняют результат до нового взвода.
- Фронт сохраняется на третьем такте после изменения кнопки. Если фронт и запись `arm` приходят в одном такте, побеждает взвод. Зажатая кнопка в момент взвода захват не запускает.
- Команда `HIGH_RES_TICK` читает `capt` и `nocap`, см. [ISA.md](ISA.md).

## Кнопка

`rtl/dev_button.v`. Параметры: `BASE` (по умолчанию `0x020`), `WIDTH` (число входов, от 1 до 32, по умолчанию 1).

- Универсальный цифровой вход. Кнопки пульта, концевые выключатели, ИК-датчик и кнопка реакции — экземпляры одного модуля с разными `BASE`. Несколько входов можно также собрать в один экземпляр через `WIDTH`.
- Вывод `btn` (от Rust) проходит синхронизатор из двух триггеров: изменение входа видно в регистре через два такта.
- Чтение по `BASE`: бит `i` — состояние входа `i`, остальные биты равны 0. Запись игнорируется.

## Светодиод

`rtl/dev_led.v`. Параметры: `BASE` (по умолчанию `0x030`), `WIDTH` (число светодиодов, от 1 до 32, по умолчанию 1).

- Регистр по `BASE`: бит `i` — светодиод `i`. Используются младшие `WIDTH` бит записи, записанное значение читается обратно. После сброса все выключены.
- Вывод `led` — для Rust.

## Ворота

`rtl/dev_gate.v`. Параметр: `BASE` (по умолчанию `0x040`).

- Регистр по `BASE`: бит 0 — открыть, бит 1 — закрыть, остальные биты игнорируются. Читается записанное значение. После сброса мотор остановлен.
- Выводы для Rust: `gate_open` и `gate_close` (мотор на открытие и на закрытие).
- Если записаны оба бита, оба вывода равны 0 (защита), а регистр читается как записан.
- Остановка по концевому выключателю — задача программы: она читает концевики (экземпляры `dev_button`) и записывает 0.

## Дисплей

`rtl/dev_display.v`. Параметров нет.

- Мост между Rust и портом чтения видеопамяти: адрес слова `frame_addr` (вход от Rust) идёт на порт `vram_raddr`, слово `vram_rdata` возвращается на `frame_data` (выход для Rust). Rust перебирает 4096 адресов и собирает кадр 128 × 128.
- Шину устройства дисплей принимает, но регистров и окна адресов у него пока нет: `rd = 0`.
- Видеопамять (`rtl/vram.v`) устройством MMIO **не является**: она лежит в своей области памяти данных (`0x00001000`–`0x00001FFF`) и доступна процессору через декодер адреса. Формат пикселей описан в [ISA.md](ISA.md).

## Как добавить устройство

1. Написать модуль с шиной выше и параметром `BASE`; ответ `rd` равен 0 при чужом адресе.
2. Выбрать свободный `BASE` и добавить строку в таблицу.
3. В `soc_top` добавить экземпляр и его `rd` в `mmio_rd`.
4. Вывести внешние выводы устройства наружу `soc_top` для Rust.
